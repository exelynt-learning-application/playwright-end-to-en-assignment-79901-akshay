Setting retries to 3 can hide real problems because a test that fails initially but passes on a later retry may still indicate a genuine bug, timing issue, or unstable application behavior. This makes the pipeline appear green even when tests are unreliable. Two improvements: (1) Enable Playwright tracing on the first retry using `trace: 'on-first-retry'` so developers can investigate failures with screenshots, logs, and network activity. (2) Mark unstable tests with `test.fail()` or use Playwright's `testInfo` retry information to report flaky tests separately, rather than silently treating them as successful. This helps the team identify, investigate, and fix flaky tests while keeping test results transparent.
